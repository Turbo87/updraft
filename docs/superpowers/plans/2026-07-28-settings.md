# Persisted Locale Setting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move locale selection from frontend `localStorage` into core-owned settings persisted by the Tauri shell, and expose it through a plain settings route.

**Architecture:** `updraft_core` owns a `Settings` value containing an optional locale and publishes it through the existing topic stream. The Tauri shell loads `settings.json` before constructing the core and executes complete-snapshot persistence effects on one background writer. The Svelte frontend reads the settings topic, sends `set_locale` commands through its client abstraction, and presents English and German choices on `/settings`.

**Tech Stack:** Rust 2024, Tauri 2.11.5, Tokio 1.53.1, Serde 1.0.229, serde_json 1.0.151, tempfile 3.27.0, Svelte 5.56.7, SvelteKit 2.70.1, TypeScript 6.0.3, Paraglide 2.22.0, Vitest 4.1.10, Playwright 1.61.1

## Global Constraints

- Follow red-green-refactor for every behavior change. Run each new test before implementation and confirm that it fails for the expected missing behavior.
- Keep `Settings` limited to `locale: Option<Locale>`. Do not add categories, device settings, units, aircraft data, profiles, or generic settings-change abstractions.
- Serialize locales as `en` and `de`.
- Treat a missing settings file as the normal default state. Do not create a file at startup.
- Do not migrate the existing frontend `localStorage` value.
- Apply locale changes in the core before persistence completes. A persistence failure logs a warning and does not roll back the active locale.
- Persist complete snapshots in order through one background writer.
- Stream JSON directly into a temporary file beside `settings.json`, flush it, and atomically replace the destination.
- Show only English and German. Preserve the existing circular flag icons and add visible text labels.
- Keep frontend selection topic-driven initially. Complete the real-Tauri responsiveness check before accepting the UI.
- Use the existing generated TypeScript protocol and hand-written fake client.
- Use exact dependency pins.
- Keep every commit green and single-purpose.

```rust
use std::fs::File;
use std::io::BufReader;
use std::path::PathBuf;
use updraft_core::Settings;

const FILE_NAME: &str = "settings.json";

#[derive(Clone, Debug)]
pub struct SettingsFile {
    path: PathBuf,
}

impl SettingsFile {
    pub fn new(config_dir: impl Into<PathBuf>) -> Self {
        Self {
            path: config_dir.into().join(FILE_NAME),
        }
    }

    pub fn load(&self) -> Settings {
        let file = match File::open(&self.path) {
            Ok(file) => file,
            Err(error) if error.kind() == std::io::ErrorKind::NotFound => {
                return Settings::default();
            }
            Err(error) => {
                tracing::warn!(path = %self.path.display(), %error, "Could not load settings");
                return Settings::default();
            }
        };

        serde_json::from_reader(BufReader::new(file)).unwrap_or_else(|error| {
            tracing::warn!(path = %self.path.display(), %error, "Could not load settings");
            Settings::default()
        })
    }
}
```

Implement writing on `SettingsFile`:

```rust
fn write(&self, settings: Settings) -> std::io::Result<()> {
    let directory = self
        .path
        .parent()
        .expect("settings path always includes its configuration directory");
    std::fs::create_dir_all(directory)?;

    let mut temporary = NamedTempFile::new_in(directory)?;
    serde_json::to_writer_pretty(temporary.as_file_mut(), &settings)
        .map_err(std::io::Error::other)?;
    writeln!(temporary.as_file_mut())?;
    temporary.as_file_mut().flush()?;
    temporary.persist(&self.path).map_err(|error| error.error)?;

    Ok(())
}
```

Do not serialize through `to_string()`, `to_vec()`, or an equivalent complete-document buffer.

- [ ] **Step 8: Add the serialized background writer**

Add:

```rust
pub fn writer(self) -> impl Fn(Settings) + Send + 'static {
    let (sender, receiver) = std::sync::mpsc::channel();

    tauri::async_runtime::spawn_blocking(move || {
        for settings in receiver {
            if let Err(error) = self.write(settings) {
                tracing::warn!(
                    path = %self.path.display(),
                    %error,
                    "Could not persist settings"
                );
            }
        }
    });

    move |settings| {
        if sender.send(settings).is_err() {
            tracing::warn!("Could not queue settings persistence");
        }
    }
}
```

The single receiver is the serialization boundary. Do not spawn one writer task per change and do not coalesce snapshots.
